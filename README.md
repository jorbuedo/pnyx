# Pnyx

**Speak freely. Prove you belong. Stay unlinkable.**

A privacy-preserving community forum on [Midnight](https://midnight.network), and a self-custody

## What it is

Pnyx is a place to argue, propose and vote where **membership is something you prove rather than
something you advertise**. You join a community under a persona that exists only there; the chain
records that *a* member joined, never which identity; and two of your personas cannot be linked to
each other or back to you. Votes are counted without anyone — moderators and operators included —
learning how you voted, and voting twice is impossible by construction rather than by policy.

Alongside it, kept deliberately separate from the forum identity, is a real wallet: Cardano and
Midnight as first-class chains, hardware wallets, multi-signature, air-gapped signing, and a
transaction review screen that shows the whole transaction instead of a summary of it.

There is **no account, no email and no password**. A key in the phone's secure hardware is the
identity, released by biometrics.

### The parts that matter

| | |
|---|---|
| **A community is a contract** | Creating one deploys a Compact contract on Midnight, at an address derived from what it was created with — so anyone can verify the community is the one it claims to be. |
| **Personas, per community** | Join as your Pnyx identity or under a name scoped to that one community. The link between them never leaves your device. |
| **Private voting** | Tallied on chain, attributed to nobody. |
| **Bans that hold** | Joining spends a one-per-community nullifier derived from your identity, so a removed member cannot return under a new persona. |
| **Invite-only, or proof-gated** | A founder can require an invite code, or a condition a Cardano wallet can prove — and the invite is then issued on chain. |
| **Direct messages** | End-to-end encrypted with MLS (RFC 9420). The relay moves bytes it cannot read. |
| **Proving on the device** | Zero-knowledge proofs are generated by a native Rust prover on the handset. No proving service ever sees the secret. |
| **A real wallet** | Cardano (native assets, NFTs, multi-recipient sends, staking, DRep delegation, swaps, shared multisig), Midnight (unshielded, shielded, DUST), and derived BTC/EVM/SOL addresses for ownership proofs. |
| **Custody you choose** | Ledger and Trezor for the non-Midnight chains, QR air-gapped signing, CIP-0301 encrypted backups, passkey recovery. |
| **Twelve languages** | English plus eleven generated locales, with locale-correct number and currency formatting. |

### What is on chain, and what is deliberately not

A public ledger is permanent and readable by everyone, which is right for a membership proof and
wrong for a conversation. So:

- **On chain:** membership, votes, moderation, and the identity anchor (a commitment, not a name).
- **Off chain:** posts, channels, community descriptions, direct messages — in the content service,
  because putting a conversation on a ledger would make it permanent and public for ever.

### Status

**Early access, on the Midnight test network.** Treat everything in it as disposable: communities,
posts and votes will not carry over to mainnet. Builds are distributed outside the app stores —
see [`infra/releases/`](infra/releases/) and the install and safety notes on
[the page](https://www.pxkq.uk/pnyx#get). Do not put real funds in a wallet this build generates;

## Layout

One codebase, React Native on both platforms, **Effect-TS** throughout. Apps consume packages;
packages connect to services.

| Path | What |
|---|---|
| [`app`](app) | The mobile app — Expo + expo-router, Unistyles. Screens live in `app/app` (Expo Router's root is `app/`). |
| [`contract`](contract) | The Compact contracts — `identity`, `circle`, `proposal`, `handle`, `payment` — plus compiled artifacts. |
| [`harness`](harness) | Proving, deploy and on-chain E2E scripts. |
| [`docs`](docs) | Behaviour docs, plans and audits. [`docs/README.md`](docs/README.md) is the map. |
| [`product`](product) | Per-screen mapping decisions and open product questions. |
| [`infra`](infra) | Everything off this box: Cloudflare, the sponsor VPS, the self-hosted indexer, the media rig, releases. [`infra/README.md`](infra/README.md) indexes the boxes. |

### Packages

All under the `@pnyx/*` scope.

| | |
|---|---|
| **Chain** | `chain-client` (headless Midnight wallet + on-chain mirror), `contract-client` (derivations, witnesses, simulator), `cardano-core`, `config` (CAIP-2 ids, flags, remote config) |
| **Crypto & custody** | `crypto` (Effect-native primitives over @noble/@scure), `signer`, `signing-service`, `hardware` (Ledger + Trezor), `tx-review` (the review IR shared by review and activity) |
| **Native modules** | `midnight-native` (Rust ZK proving + curve math), `compact-hermes` (the on-chain runtime without WebAssembly, so the Compact driver runs on Hermes), `passkey-native` (platform passkeys + WebAuthn PRF), `blockstore-native`, `model-native` (on-device LLM) |
| **Wallet & storage** | `wallet`, `store` (SQLite / IndexedDB / LevelDB), `storage` (MMKV on RN), `migrations` |
| **Surfaces** | `dapp-connector` (mobile CIP-30), `links` (deep links), `mcp-server`, `identicon`, `logger`, `ur` |

## Develop

The Cardano layer comes from a fork of
[`evolution-sdk`](https://github.com/IntersectMBO/evolution-sdk), vendored as a git submodule.
**Clone with it, or nothing resolves:**

```sh
git clone --recurse-submodules <this repo>
git submodule update --init          # already cloned
```

```sh
bun install
bun run build          # builds the fork FIRST, then the workspace dists
bun run check          # type-check (three passes: project graph, uncovered packages, tests)
bun run test           # vitest
bun run lint           # biome

bun dev:android        # run the app on a device or emulator (or dev:ios)
bun chain:up           # local Midnight network (podman)
bun e2e:local          # deploy the contract + full on-chain E2E
```

⚠️ **`bun run build` builds the submodule for you** (`scripts/build-fork.ts`, also
`bun run build:fork`), and is a no-op once it is healthy. Run `bun install` first: the script
repoints the fork's `effect` at this repo's copy and needs it to exist. Three things about the fork's
build break this one, and the script handles each:

- **The fork's own `pnpm build` exits 1 on a clean clone.** Its root build is `turbo build` over a
  workspace including `docs` and `examples/*`, and `docs#build` fails with 30 fumadocs/acorn MDX
  parse errors — then fails again, differently, once `effect` is repointed, because Turbopack will
  not follow a symlink out of the fork's tree. Neither failure touches anything here, so the script
  builds `--filter './packages/*'`: 14 tasks, no docs, no examples.
- **An unbuilt submodule does not fail as "unbuilt".** Pnyx resolves `@evolution-sdk/*` to the
  fork's `dist/*.d.ts`; with no `dist` those mappings miss, TypeScript falls through to the fork's
  SOURCE, and this repo's stricter config reports thousands of errors inside it (measured: 2,124).
- **Two copies of `effect` do not typecheck against each other.** Every copy under the fork is
  repointed at this repo's, the pnpm store included: `packages/*/node_modules/effect` alone leaves
  **14** errors, because the store copy (`node_modules/.pnpm/effect@*/node_modules/effect`) is what
  the fork's emitted `.d.ts` files refer to.

The package list comes from `tsconfig.base.json`'s paths, not a list inside the script. By hand:

```sh
cd vendor/evolution-sdk && pnpm install && pnpm exec turbo build --filter './packages/*' && cd ../..
find vendor/evolution-sdk -path '*/node_modules/effect' -not -type l \
  -exec sh -c 'rm -rf "$1" && ln -s "$PWD/node_modules/effect" "$1"' _ {} \;
```

⚠️ If an earlier attempt failed, add `--force`: `tsc -b` caches the failure in `tsbuildinfo` and
will keep reporting it after the cause is fixed.

Before the first build on **either** platform, two more steps:

```sh
cd app
for f in GoogleService-Info.plist GoogleService-Info.dev.plist \
         google-services.json google-services.dev.json; do cp "$f.example" "$f"; done

bash ../packages/midnight-native/scripts/build-android.sh   # Rust -> android/src/main/jniLibs
bash ../packages/midnight-native/scripts/build-ios.sh       # Rust -> MidnightNative.xcframework
```

⚠️ **The Firebase copies are needed for Android too, not just iOS**, and this said iOS only until
2026-10-25. `app.config.js` points a dev build at `./google-services.dev.json`, so without it
`expo prebuild --platform android` fails outright:

```
✖ Prebuild failed
Error: [android.dangerous]: withAndroidDangerousBaseMod: Cannot copy google-services.json
  from app/google-services.dev.json ... Ensure the source and destination paths exist.
```

⚠️ **The Rust step has the nastier failure mode on Android.** iOS fails to *link* without its
xcframework, which is loud. Android builds an APK with no `libmidnight_native.so` in it and then
throws at runtime, where `requireNativeModule` is how absence is detected -- which has previously
taken down a whole provider tree. Needs rustup with the Android targets and an NDK
(`ANDROID_NDK_HOME`, or the highest under `$ANDROID_HOME/ndk`).


### Shipping a pre-release build

```sh
cd app && bun run preview:build:android         # → app/dist/pnyx-preview.apk
cd .. && bun infra/releases/publish.ts android app/dist/pnyx-preview.apk
```

The landing page picks it up on the next load, with no redeploy. Details, and why there is no iOS
download: the private repo's infra notes.

## Contributing

[`CLAUDE.md`](CLAUDE.md) is the contributor guide, for humans and coding agents alike — production

test hygiene, i18n, styling, and PR discipline. Read it before the first change; it is short on

### Deploying the content service

Its identity-row decoder is a build output rather than a committed file, and its config carries ids
that are yours to fill:

```sh
bash services/content/scripts/build-wasm.sh
cp services/content/wrangler.example.jsonc services/content/wrangler.jsonc
```

⚠️ There is no committed lockfile: this tree repoints its workspaces at `vendor/evolution-sdk`, and
a lockfile is keyed on resolved paths, so one from elsewhere would be wrong. `bun install` writes
your own.

✅ Verified end to end on 2026-10-19: clean export, submodule initialised, fork built, every
`effect` repointed, `bun run build` green.
